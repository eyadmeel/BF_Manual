# BF Manual (BeFirst)

**화재가 나면, 내가 움직일 수 있는 방식에 맞는 대피 경로를 알려주는 모바일 웹앱입니다.**

같은 화재라도 걸을 수 있는 사람과 휠체어를 탄 사람이 가야 할 곳은 다릅니다. BF Manual은 사용자가 "지금 어떻게 움직일 수 있는지"를 선택하면, 실제 건물 도면을 기반으로 **가장 안전한 경로를 알고리즘으로 계산**하고, 그 경로를 **AI가 사람이 읽을 수 있는 행동 안내문으로 바꾸고**, **AR 카메라 화면 위에서 방향을 알려줍니다.**

> 2026 해커톤 출품작 · 시연 기준: 전시동 2층, 205호 출발, "2층 동측 홀 화재" 시나리오

## 1. 왜 만들었나

화재 대피 안내는 보통 "가장 가까운 비상구로 대피하세요" 한 가지뿐입니다. 하지만 계단을 이용할 수 없는 사람(휠체어 이용자, 거동이 불편한 사람)에게 "계단으로 내려가 비상구로 나가라"는 안내는 쓸 수 없는 안내입니다.

BF Manual은 이 문제를 두 가지 원칙으로 풀었습니다.

- **경로는 사람이 아니라 알고리즘이 정확하게 계산한다.** 이동 상태에 따라 지나갈 수 없는 구간(계단, 좁은 통로, 단차)을 제외하고 최단 안전 경로를 찾습니다.
- **계단 이용 가능 여부가 목적지 자체를 바꾼다.** 계단을 쓸 수 있으면 1층 비상구로 건물 밖까지, 쓸 수 없으면 같은 층 방화구획 대피공간(구조 대기 장소)으로 안내합니다. 이것이 이 서비스의 가장 큰 차별점입니다.

## 2. 무엇을 할 수 있나 (기능)

### 2.1 이동 상태 선택
사용자는 시작 화면에서 자신의 상태를 4가지 중 하나로 선택합니다.

| 이동 상태 | 의미 | 목적지 |
| --- | --- | --- |
| 혼자 이동 가능 | 계단 포함 자유롭게 이동 | 1층 비상구 (건물 밖) |
| 보행 보조기구 사용 | 지팡이·목발 등, 계단은 가능하지만 힘듦 | 1층 비상구 (건물 밖) |
| 휠체어 이용 | 계단·단차 이용 불가 | 같은 층 대피공간 (구조 대기) |
| 이동 불가 | 스스로 이동이 어려움 | 그 자리 대피 행동요령 (구조 대기) |

### 2.2 현재 위치 기반 경로 계산
평면도에서 지금 있는 방을 탭하면, 그 위치를 기준으로 경로가 즉시 계산되어 도면 위에 그려집니다. 경로 주변으로 화면이 자동 확대됩니다.

### 2.3 AI 행동요령 안내
계산된 경로를 "205호에서 나와 오른쪽 복도를 따라가세요" 같은 사람이 읽기 쉬운 단계별 문장으로 바꿔 보여줍니다. 도착지 종류(비상구/대피공간)에 맞는 마무리 행동(문 닫기, 119 신고 등)도 함께 안내합니다.

### 2.4 매뉴얼 기반 근거 (RAG)
AI가 문장을 지어내는 게 아니라, 소방청·장애인 화재 대피 관련 공식 매뉴얼 문서에서 관련 문단을 찾아 그 내용을 참고해 안내문을 만듭니다. 이동 상태와 목적지 종류에 맞는 문단만 골라 씁니다(예: 휠체어 이용자에게는 계단 하강 안내가 섞이지 않습니다).

### 2.5 상황 변화 대응 (우회 재탐색)
시연 중 "서측 복도 차단" 같은 새로운 위험 상황이 발생하면, 현재 위치를 기준으로 경로를 즉시 다시 계산해 새 경로와 바뀐 이유를 보여줍니다.

### 2.6 이동 불가 사용자를 위한 그 자리 대피 안내
"이동 불가"를 선택한 사용자에게는 AR 대피 안내 대신, 평면도 아래에 그 자리에서 할 수 있는 행동요령(문 닫고 틈 막기, 119 신고, 창문·소리로 신호 보내기 등)을 고정 안내로 보여줍니다.

### 2.7 AR 카메라 대피 안내
앱 설치 없이 브라우저만으로, 후면 카메라 화면 위에 방향 화살표를 겹쳐 보여주며 실제로 그 방향을 향해 걷도록 안내합니다.
- 폰을 어느 쪽으로 들고 있어도 화면상 화살표가 실제 목표 방향을 정확히 가리키도록 자동 보정합니다.
- 걸음을 인식해 이동 거리가 쌓이면 다음 구간 방향으로 화살표가 자연스럽게 바뀝니다.
- 진행 경로가 담긴 축소 지도를 함께 보여주고(더블탭/두 손가락으로 확대·축소), 카메라 앞 큰 장애물을 자동으로 알려줍니다.
- 도착하면 목적지 종류에 맞는 마무리 안내(비상구로 나가기 / 대피공간에서 대기)를 보여줍니다.

### 2.8 도움 요청 미리보기
경로·현재 위치·이동 상태를 담은 도움 요청 문구를 만들어 보여줍니다. (개인정보는 입력받지 않으며, MVP 범위에서는 실제 전송은 하지 않고 미리보기까지만 제공합니다.)

### 2.9 실패해도 안내는 멈추지 않음
- 경로를 찾을 수 없으면 → "가까운 방화문 안쪽으로 대피 + 119 신고" 안내로 대체합니다.
- AI 서버 호출이 안 되거나 느리면 → 미리 준비된 템플릿 행동요령으로 대체합니다.
- 카메라 권한이 없거나 카메라가 없어도 → 화살표·문구 기반 안내는 계속 동작합니다.

## 3. 어떻게 작동하나 (핵심 기술)

### 기술 1. 이동 상태별 맞춤 경로 계산 (결정론적 다익스트라)

건물을 **노드**(방, 복도 분기점, 계단, 대피공간, 비상구)와 **엣지**(문, 복도, 계단 — 각각 거리·통로폭·단차 정보 포함)로 이루어진 그래프로 표현합니다. 이 위에서 **다익스트라 알고리즘**으로 최단 안전 경로를 계산합니다. AI는 이 계산에 전혀 관여하지 않습니다.

이동 상태별로 지나갈 수 있는 구간이 다릅니다.
- **계단 이용 불가**(휠체어·이동 불가): 계단 엣지 자체를 탐색 대상에서 제외 → 목적지 후보도 같은 층 대피공간으로 제한됩니다.
- **단차·통로 폭 제약**: 보행 보조기구·휠체어 이용자는 단차가 있는 구간, 필요한 통로 폭(80~90cm)보다 좁은 구간을 지날 수 없습니다.
- **가중치로 우회 유도**: 완전히 막힌 건 아니지만 피하는 게 나은 구간(예: 보행 보조기구 이용자의 계단)은 통과 비용을 3배로 매겨, 다른 길이 있으면 그쪽을 먼저 선택하게 만듭니다.

화재 정보도 같은 방식으로 반영됩니다. 완전 차단 구역은 탐색에서 제외하고, 연기 구역은 비용을 3배로 올려 가능하면 우회하되 다른 길이 없으면 최후 수단으로 통과시킵니다. 상황이 바뀌면 현재 위치를 새 출발점으로 두고 다시 계산해 우회 경로를 즉시 만들어냅니다.

같은 입력에는 항상 같은 결과가 나오므로 테스트로 정확성을 검증할 수 있습니다(`backend/tests/test_pathfinder.py`).

### 기술 2. LangGraph 기반 행동요령 생성 Agent (+ 매뉴얼 검색)

다익스트라가 계산한 결과는 노드 목록일 뿐이라 사람이 읽기 어렵습니다. 이를 단계별 행동 문장으로 바꾸는 과정을 **LangGraph** 상태 그래프로 구성했습니다.

```
요약(summarize) → 매뉴얼 검색(retrieve) → 생성(generate) → 검증(validate)
                                                              ├─ 통과 → 최종 안내(finalize)
                                                              └─ 실패 → 템플릿 폴백(fallback)
```

- **요약**: 계산된 경로, 목적지 종류, 연기 통과 구간을 LLM 입력용으로 정리합니다.
- **매뉴얼 검색(RAG)**: 소방청·장애인 화재 대피 공식 매뉴얼 문서를 미리 문단 단위로 인덱싱해두고, 이동 상태·목적지 종류에 맞는 태그(exit/refuge/shelter/common)로 먼저 거른 뒤 의미 유사도로 관련 문단을 찾습니다. 1.5초 안에 끝나지 않거나 실패하면 참고 자료 없이 다음 단계로 진행합니다.
- **생성**: LangChain으로 OpenAI를 호출해 제목·단계별 행동·주의사항을 JSON으로 받습니다. 프롬프트에는 "주어진 경로를 바꾸거나 새로운 방향·층·출구를 제시하지 말 것"을 명시해 AI가 경로 결정에 관여하지 못하게 막습니다.
- **검증**: 필수 항목 누락, 금지 표현(엘리베이터·승강기) 포함 여부를 검사합니다. 걸리면 무조건 템플릿 폴백으로 전환됩니다.

API 키가 없거나, OpenAI 호출이 실패·시간 초과되거나, 매뉴얼 검색이 실패하거나, LangGraph 라이브러리를 불러올 수 없어도 — 모든 경우에 템플릿 기반 안내로 흐름이 끝까지 동작합니다.

### 기술 3. 경로 연동 웹 AR 대피 안내

앱 설치 없이 모바일 브라우저만으로 동작하는 AR 안내입니다.

- **좌표 체계 통일**: 노드 좌표를 평면도 이미지 기준 퍼센트 좌표로 저장해, 평면도 화면·AR 지도·AR 화살표가 모두 같은 좌표를 공유합니다.
- **실시간 방향 회전**: 폰의 방위 센서 값과 목표 방향의 차이만큼 화살표가 돌아갑니다. AR을 켠 순간 바라보던 방향을 기준으로 보정하기 때문에, 실제 건물 방향과 평면도 방향이 달라도 안내가 맞습니다.
- **구간별 진행 판정**: 경로를 구간으로 나누고, 가속도 센서로 걸음을 인식해 이동 거리가 쌓이면 다음 구간 방향으로 화살표를 갱신합니다. 이동 상태별로 보폭을 다르게 계산합니다.
- **우회 재탐색 연동**: AR 화면에서 "다른 안전 출구 찾기"를 누르면 현재 위치를 노드로 환산해 백엔드에 재탐색을 요청하고, 새 경로로 화면을 다시 그립니다 — AR도 결국 기술 1의 다익스트라 엔진에 의존합니다.
- **현장 보조 기능**: 경량 사물 인식 모델로 큰 장애물을 알려주고, 방향 전환·도착·재탐색 결과를 음성으로도 안내합니다.

## 4. 화면 구성

| 화면 | 이름 | 하는 일 |
| --- | --- | --- |
| 1 | 이동 상태 선택 | 4가지 이동 상태 중 선택, "다음" 클릭 시 카메라 권한 요청 |
| 2 | 평면도 · 경로 · 행동요령 | 현재 위치 탭 → 경로 계산 → AI 행동요령 표시. 이동 불가는 그 자리 대피 행동요령으로 대체 |
| 3 | AR 대피 안내 | 후면 카메라 위 방향 화살표, 구간 전환, 우회 재탐색, 도움 요청 미리보기 |

```
│  │  ├─ ar-core.js                # AR 방향 계산 로직
│  │  ├─ vendor/tailwind-play.js   # Tailwind (로컬 스크립트)
│  │  └─ screens/                  # screen1.js, screen2.js, screen3.js
│  ├─ assets/                      # 로고 등
│  └─ ar/assets/                   # 층별 평면도 이미지
├─ docs/                           # 기획서, 평면도, 발표자료, 핵심기술 정리
├─ api/index.py                    # Vercel 서버리스 진입점
├─ vercel.json                     # Vercel 배포 설정
└─ requirements.txt                # Vercel 배포용 (backend/requirements.txt와 동일)
```

### 구조를 이렇게 잡은 이유

- **`api/`와 `services/` 분리** — 경로 계산 로직을 Flask 없이도 단독 실행·테스트할 수 있습니다. 서버를 안 띄워도 로직만 검증 가능합니다.
- **`data/`를 코드와 분리** — 평면도 담당자가 Python을 몰라도 JSON 파일만 수정하면 됩니다. 여러 명이 동시에 작업해도 충돌이 적습니다.
- **`guide_agent.py`를 경로 엔진과 분리** — OpenAI 호출이 실패해도 경로 계산과 안내 자체는 영향받지 않습니다.
- **프론트엔드를 Flask가 함께 서빙** — 별도 서버나 CORS 설정 없이 `localhost:5000` 하나로 전체 시연이 가능합니다.

## 8. 실행 방법

### 로컬 (PC 브라우저로 확인)

```bash
cd backend
pip install -r requirements.txt
cp .env.example .env        # OPENAI_API_KEY 입력 (없어도 템플릿 폴백으로 동작)
python run.py
```

브라우저에서 `http://localhost:5000` 접속.

### 모바일로 카메라·AR 확인

카메라와 방위 센서는 **HTTPS 또는 localhost**에서만 동작합니다. `192.168.x.x` 같은 사설 IP 주소(HTTP)로 접속하면 브라우저가 카메라를 차단합니다.

- **가장 간단한 방법**: Vercel에 배포한 HTTPS 주소로 폰에서 접속합니다. ([11. 배포](#11-배포) 참고)
- **USB로 PC와 연결**: PC에서 `python run.py`로 서버를 띄운 뒤, 크롬 `chrome://inspect` 등으로 포트를 포워딩해 폰에서 `localhost:5000`으로 접속합니다.

### 매뉴얼 검색(RAG) 인덱스 새로 만들기

`backend/app/data/manuals/*.md`를 추가·수정했다면 인덱스를 다시 생성해야 합니다.

```bash
python backend/scripts/build_manual_index.py --check   # 형식 검사만 (네트워크 불필요)
python backend/scripts/build_manual_index.py           # 통과 시 인덱스 생성/저장
```

## 10. 설계 원칙 (지켜야 할 것들)

1. **AI는 경로를 만들지 않는다.** 경로는 Node/Edge 그래프 + 다익스트라가 결정론적으로 계산하고, AI는 계산된 경로를 사람이 읽을 문장으로 바꾸는 역할만 한다.
2. **경로는 방(room) 내부·문(door)·복도(corridor)만 통과한다.** 벽을 가로지르는 연결은 만들지 않으며, room → corridor는 반드시 door 타입 엣지를 거친다.
3. **계단 이용 가능 여부가 목적지를 가른다.** 계단 가능 → 1층 비상구, 계단 불가 → 같은 층 대피공간. 이 분기는 어떤 변경에서도 유지한다.
4. **실패해도 반드시 무언가를 안내한다.** 경로 없음 → 방화문 안쪽 대피 + 119 안내. AI 호출 실패 → 템플릿 행동요령. API 키가 없어도 전체 흐름이 끝까지 동작해야 한다.
5. **화재 시 엘리베이터를 안내하지 않는다.** 출력 검증 단계에서 관련 표현을 차단한다.
6. **개인정보를 입력받지 않는다.** 이름·연락처 등을 요구하지 않으며, 도움 요청은 '미리보기 텍스트'까지만 제공하고 실제 전송은 MVP 범위 밖이다.

## 11. 배포

- **Vercel** 서버리스로 배포합니다. `api/index.py`가 Flask 앱을 WSGI로 감싸는 진입점이고, `vercel.json`이 모든 요청을 그쪽으로 라우팅합니다.
- 배포용 `requirements.txt`(저장소 루트)는 `backend/requirements.txt`와 항상 동일하게 유지해야 합니다.
- 시연 시 폰은 반드시 `https://` 주소로 접속합니다. 사설 IP(`http://`)로는 카메라·센서가 동작하지 않습니다.

## 12. 알려진 한계 / 추후 확장

현재 구현 대상이 아니며, 발표에서는 "추후 확장" 방향으로만 언급합니다.

- **실내 측위 연동**: 지금은 걸음 인식(가속도 센서)으로 이동 거리를 추정합니다. 실제 실내 위치 측위 기술과 연동하면 더 정밀해집니다.
- **IoT 화재 감지기 연동**: 지금은 미리 준비한 시연 시나리오(`hazard_scenarios.json`)로 화재 상황을 재현합니다. 실시간 화재 감지 센서와 연동할 수 있습니다.
- **도움 요청 실제 전송**: 지금은 문구 미리보기까지만 제공합니다. 문자·카카오톡·전화 등 실제 전송 기능은 MVP 범위 밖입니다.
